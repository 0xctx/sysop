# sysop

A Claude Code plugin that carries one change, or a batch of changes, to a checked, independently reviewed, landed state using `claude`, `agy` and `pi`. Markdown skills and read-only agents own judgment; one stdlib script owns mechanics; three hooks own guarantees. No server, database or build step. Stack: Python ≥3.11 standard library, markdown, git, the `claude`/`agy`/`pi`/`gh` CLIs (and `kaggle`, opt-in).

Design: `docs/architecture.md`; reference: `docs/guide.md`; credits: `docs/lineage.md`.

## Map
- `.claude-plugin/`: `plugin.json` and `marketplace.json` (`source: "./"`; the repo root is the plugin root).
- `skills/<name>/SKILL.md`: one skill per directory; detail goes in that skill's `references/` or `templates/`.
- `agents/*.md`: read-only reviewer and explorer agents.
- `hooks/`: `hooks.json` plus `guard.py` (PreToolUse), `context.py` (SessionStart), `stop_gate.py` (Stop: holds the turn open during an active run; opt-in check gate). `sysop.mod.jsx`: the mod (Claude Code 2.1.287+), which runs inside Claude Code: `/sysop` runs the `sysop.py` command the operator typed at zero tokens; a destructive git command the guard stopped can be run once from a dialog the operator presses (never credentials, forged records or attribution). It shows, wakes and runs; it never decides, and everything works with it off. Its tests are `tests/mod/*.test.ts` (`claude plugin test .`, local only, like `claude plugin validate`).
- `scripts/sysop.py`: the CLI over every mechanic (`python3 scripts/sysop.py --help` lists the everyday ones, `--help-all` every one). Behind it: `store.py` (store, settings, shared helpers; the only module hooks import, except the context hook's one call to `presets.status_line`, which reads only cached facts), `workers.py` (roster, routing, cooldowns, launch/wait, cross-family review, the `models` command), `advice.py` (the opt-in intel layer: facts, catalog scoring, auto chains, doors, budget, follow_latest, advise, learn; imported lazily, never by core routing or hooks), `land.py` (review gate, land, cleanup, pr, reports), `fleet.py` (the ticket graph, `next`, halt, fallback, run markers, notify, ledger, race), `verify.py` (the opt-in runtime verifier: start the app, a fresh verifier drives the journeys, calibration, the land gate), `health.py` (`status` and `doctor`: one screen each, never creating the store), `presets.py` (named model presets: list, show, diff, use, save, their safety rules and readiness; shipped files in `presets/`, whose `claude-plan` equals the built-in defaults); imports run store ← workers ← fleet, store ← land ← fleet, workers ← presets ← health, fleet ← health, and workers ← advice (loaded on demand), never back. `scripts/intel.py` and `scripts/repo_profile.py`: model facts and scoring, and what a repository is (pure; `advice.py` owns their caches, hooks only read them). `scripts/catalog.json`: shipped model estimates. `scripts/prose_check.py`: the writing gate (pure). `scripts/kaggle_jobs.py` and `scripts/kaggle_serve.py`: Kaggle batch jobs and opt-in session serving (sysop.py's `kaggle` and `serve`); `scripts/kaggle/`: `common.py` (every notebook's head) plus one template per use, and the model list. `scripts/lint.py`: the craft and budget gate.
- `.claude/{plans,reports,code-reviews}/`: per-ticket PIV artifacts (plan, implementation report, review) in the development repo; `sysop.py publish` leaves them out of the public export.
- `tests/`: `unittest` suites, run offline; `tests/e2e/`: headless `claude -p --plugin-dir` scripts (they cost tokens and are run deliberately).

## Ground rules
- Mechanics go in `scripts/`, behind the `sysop.py` CLI, as a subcommand with offline tests, never as shell snippets in skill prose (agents skip them). Skills call it through dynamic context or one command line.
- A skill that uses `` !`python3 ${CLAUDE_PLUGIN_ROOT}/scripts/sysop.py …` `` must declare `allowed-tools: Bash(python3 ${CLAUDE_PLUGIN_ROOT}/scripts/sysop.py *)`, and the `!` must follow whitespace. Otherwise headless runs silently abort the skill. The injected command must also exit 0 outside a git repo; `scripts/lint.py` checks the coverage.
- Artifacts live in `.sysop/` at the main checkout root (`sysop.py store`), never inside `.git/` and never in a worktree.
- Worktrees sysop creates live under `.sysop/wt/`; `land` removes only those and never touches the operator's own. Check commands run through `run_check` (own process group, killed whole on timeout). A worker's deadline is recorded at launch and enforced from Python (`enforce_deadline`, on every read of its state), never by GNU `timeout`, which macOS lacks.
- Data crosses into scripts through flags or JSON; scripts never parse prose files such as `.sysop/tickets.md` or a PRD (the slice skill writes slices JSON; `ticket import` reads it).
- Records that only sysop.py writes (ledger, tickets, runs, active runs, races, cross-family results, review seals, verifications and the calibration, cooldowns) are guard-protected; the ledger derives worker, model and fallbacks from launch records, never from an agent's claim.
- Lanes are settings (`lanes`), applied by the global `--lane` flag through `load_settings` (the lane's preset, cap and landing authority over the repo's settings); a ticket records its lane, and `next` gives each lane its own cap and authority. Repos with tickets register in `~/.cache/sysop/repos.json` for `next --all` and `status --all`; a dependency on another repo's ticket is `<repo folder>:<ticket>` and must land first (no stacking across repos).
- Model choices live only in settings (`sysop.py models` shows and changes them); skills never hardcode a model.
- The built-in workers `claude`, `agy` and `pi` are defined only in code; settings cannot redefine them. pi-free's resold pools (`pi:cline/…`) are never a default: auto chains and doors use them only when the operator puts one in a tier.
- Model family is the vendor, detected from the full model id, never from the CLI (agy also serves Claude models). One model reached through several CLIs or providers shares `intel.model_key`; the door fallback (setting `doors`) is the only implicit reroute, and it is recorded as `door_for`.
- One effort vocabulary (`low…max`), translated per CLI only in `workers.py`'s effort table. Skill scores: benchmarks beat the shipped estimates in `scripts/catalog.json`, and the operator's `catalog` setting beats both.
- Hooks: exit 2 blocks and exit 1 does not; context goes in `hookSpecificOutput.additionalContext`; the Stop check gate stands down on `stop_hook_active`, but the run gate uses progress-based anti-spin because that flag stays true after the first block; internal errors exit 0. A hook change needs tests in both directions. A block message never describes a way around the block (an agent once ran `! cmd`, which bash reads as negation, after being told to).
- Skills: the `name` equals the directory; description plus `when_to_use` stay at or below 1,536 characters; bodies stay under 500 lines; every bundled file is linked from the body. User-only skills set `disable-model-invocation: true`. The always-loaded budget is about 1.3k tokens of description text (`scripts/lint.py` measures exactly that: descriptions only, user-only skills free). `claude plugin details sysop` projects the all-in cost, about 2.4k on 2026-10-12: it adds per-entry framing (~30 tokens each), counts the agents and, apparently, the user-only skills, so treat it as an upper bound.
- Git: one focused commit per milestone, on a feature branch fast-forwarded into `main`. No AI attribution in commits or PRs. Use `git branch -d`, never `-D`; work sysop must discard (race losers) is first committed and archived under `refs/sysop/race/`.
- Worker logs are read through `worker_output` (claude workers print a JSON result); costs come only from what a CLI states, never estimates.
- Skills name each other `sysop:<name>` (built-in skills collide otherwise) and create plans and reports with `sysop.py report`. Every landing path (`land` locally, `pr merge` on GitHub) passes `review_gate`: exactly one `Verdict: READY`, a script-written cross-family result, and a seal (`sysop.py review seal`, review's last step) binding that report's bytes to the branch head, checked before any rebase, and, when `start` is set, a calibrated verifier's PASS at that same commit; the guard refuses a raw `gh pr merge` or remote branch delete for `sysop/*` and `race/*` branches and during an active sysop run (the guard runs in every session, so its workflow rules stop at sysop's own work). Long skills bracket themselves with `sysop.py run start --session ${CLAUDE_SESSION_ID}` / `run end`.
- Kaggle: ML work only (its Acceptable Use Policy); every notebook stops itself (the CLI cannot stop a session), and GPU use is proven by GPU memory in use, never assumed. A served endpoint is always keyed; keys and tokens are never printed or logged.
- Don't create a root `CLAUDE.md` (`claude plugin validate` warns about it; Claude Code already loads this file).

## Commands
- `python3 -m unittest discover -s tests`: all offline tests.
- `python3 scripts/lint.py .`: skill and agent craft, hook wiring, context budget.
- `claude plugin validate .`: manifests and component paths.
- `claude -p "<prompt>" --plugin-dir <this repo> --model haiku`: an end-to-end run on a scratch repo (in the scratchpad, never this repo). e2e runs share the operator's HOME; `tests/e2e/lib.sh` fails any run that changes their memory or settings.

## Working principles
- Contract first: problem, why, why now, outcome, invariants, acceptance.
- Prose is a claim; code is the fact. Verify against the source before acting on any doc, plan or report.
- Smallest truthful system: delete before adding; every guard needs a test that has seen it fire.
- Evidence over assertion: done means an external check went green; report what passed, what failed and what is untested.
- Independent review in a fresh context, preferably by another model family.
- Artifacts, not summaries, cross context boundaries.
- Authority is explicit: landing needs the operator's word or a standing grant; force-push and discarding work always need the operator's word.
- Paperwork scales with risk: tiny work skips the plan, never the checks.
- Never edit files that a running end-to-end test loads, nor the operator state it watches (memory, user settings).
- Verify a platform assumption by its mechanism before building on it (the GPU is in use, not that tok/s looks fine; the secret is read, not that the push is accepted).
